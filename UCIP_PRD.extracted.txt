1. Product Overview
1.1 One-Line Summary
UCIP is a web/mobile app that crowdsources neighbourhood-level climate data from Lagos residents and fuses it with satellite imagery and weather APIs to produce real-time urban heat maps, flood risk dashboards, and green space health trackers.
1.2 Problem Statement
Lagos has zero neighbourhood-level climate monitoring. Federal weather stations provide city-wide readings but cannot detect localised heat islands, ward-level flood risk, or vegetation loss at the community scale. Residents have no way to know their neighbourhood’s climate risk, and planners have no data to prioritise interventions.

2. System Architecture
2.1 High-Level Architecture
The system follows a three-tier architecture with clear separation between data ingestion, processing, and presentation layers.
Client Layer (React.js + Tailwind CSS)
Single-page application served from Vercel. Leaflet.js renders interactive map layers. Progressive Web App (PWA) enabled for mobile install. Communicates with backend via REST API.
API Layer (Node.js + Express)
RESTful API server hosted on Vercel Serverless Functions. Handles authentication, report ingestion, data aggregation, and alert dispatch. Connects to Supabase for persistence and external APIs for satellite/weather data.
Data Layer (Supabase / PostgreSQL + PostGIS)
Supabase provides managed PostgreSQL with PostGIS spatial extensions. Stores citizen reports with geo-coordinates, aggregated heat scores, flood risk calculations, and NDVI time-series data. Real-time subscriptions power live dashboard updates.
External Integrations
2.2 Data Flow
1. Citizen submits report → POST /api/reports → validated → stored in Supabase with PostGIS point geometry.
2. Cron job (every 15 min) → fetches Open-Meteo forecast → stores latest readings per LGA.
3. Daily batch → pulls MODIS land surface temperature + Landsat NDVI from Earth Engine → rasterises to neighbourhood grid → stores aggregated scores.
4. Aggregation engine → combines citizen reports + satellite + weather → computes heat_score, flood_risk_score, ndvi_health per neighbourhood.
5. Alert engine → checks thresholds → fires Firebase push + SMS via Africa’s Talking to subscribed residents.
6. Client fetches → GET /api/heatmap, /api/flood-risk, /api/ndvi → Leaflet renders layers.

3.3 Scoring Algorithms
Heat Score (0–10)
heat_score = (0.4 × normalised_satellite_LST) + (0.35 × normalised_citizen_severity) + (0.25 × normalised_api_temperature)
Where normalised values are min-max scaled within the city range. Citizen severity is the average of reports in the last 6 hours within the neighbourhood boundary, weighted by recency.
Flood Risk Score (0–10)
flood_risk = (0.3 × forecast_rainfall_norm) + (0.25 × historical_flood_freq) + (0.25 × elevation_risk) + (0.2 × citizen_flood_reports_norm)
Elevation risk is inverse of SRTM elevation relative to local drainage basins. Historical flood frequency is computed from cumulative citizen reports.
NDVI Health (0–1)
Direct NDVI reading from Landsat/MODIS, averaged per neighbourhood polygon. Values below 0.3 trigger “vegetation loss” alerts. Week-over-week decline exceeding 0.05 triggers “active clearing” alert.

6. Module 1: Urban Heat Mapping
Data Sources
Satellite: MODIS Land Surface Temperature (MOD11A1) via Google Earth Engine — 1km resolution, daily. Landsat 8/9 thermal bands for higher-res (100m) snapshots.
Weather API: Open-Meteo hourly temperature at Lagos coordinates.
Citizen reports: Heat severity ratings (1–5) with GPS, aggregated by neighbourhood.
Processing Pipeline
1. Daily cron pulls MODIS LST for Lagos bounding box from Earth Engine.
2. Rasterise to neighbourhood polygons (pre-defined GeoJSON for 100 Lagos neighbourhoods).
3. Normalise satellite temp to 0–10 scale.
4. Every 15 min: fetch Open-Meteo current temp, normalise.
5. Every 15 min: aggregate citizen reports from last 6 hours per neighbourhood, compute mean severity, normalise.
6. Compute heat_score = 0.4×satellite + 0.35×citizen + 0.25×weather.
7. Store in neighbourhood_scores table.
Rendering
Leaflet.heat plugin reads /api/heatmap response. Each grid point [lat, lng, heat_score] rendered as heatmap intensity. Colour scale: green (0–3) → yellow (4–6) → red (7–10).
7. Module 2: Flood Risk Intelligence
Data Sources
Rainfall forecast: Open-Meteo 6-hour precipitation forecast.
Elevation: SRTM 30m DEM, pre-processed to identify low-lying zones per neighbourhood.
Citizen reports: Flood severity reports with GPS.
Historical frequency: Running count of flood reports per neighbourhood over time.
Alert Logic
IF forecast_rainfall > 30mm AND flood_risk_score > 6 THEN trigger flood alert for affected neighbourhoods. Alert sent via Firebase push notification to subscribed users + SMS via Africa’s Talking to registered phone numbers in the affected LGA.
8. Module 3: Green Space Tracker
NDVI Pipeline
1. Pull Landsat NDVI composites from Earth Engine (bi-weekly).
2. Clip to neighbourhood polygons.
3. Compute mean NDVI per neighbourhood.
4. Compare to previous period: flag decline > 0.05.
5. Store time-series in neighbourhood_scores.
Leaderboard
GET /leaderboard returns neighbourhoods sorted by NDVI descending. Frontend renders progress bars. Colour: green (>0.5), yellow (0.3–0.5), red (<0.3).
9. USSD Integration
USSD flow via Africa’s Talking API. Callback endpoint: POST /api/v1/ussd/callback.
Menu Flow
Dial *384*UCIP#
Screen 1: Welcome to UCIP. Select:
1. Report Heat
2. Report Flood
3. Report Tree Clearing
4. Check My Area
Screen 2 (Report Heat): Rate heat severity:
1. Mild
2. Moderate
3. Hot
4. Very Hot
5. Extreme
Screen 3: Location? 
1. Use phone location
2. Type neighbourhood name
Screen 4: Report submitted! ID: RPT-2847. You will receive alerts for your area. END.
Session state tracked via Africa’s Talking sessionId. Each interaction maps to a report_type + severity + location, then calls the same POST /reports endpoint with source: “ussd”.

npm run api  # API at localhost:3001
